# AutoTouch 微信来电自动接听 + 日历时钟常驻 使用说明

配套脚本：`wechat_auto_answer.lua`（AutoTouch 用，Lua 5.3）。

## 功能

- 平时保持指定日历/时钟 App 在前台显示（默认系统日历，可改）。
- 每 10 秒检测一次微信来电（视频/语音），自动点击“接听”，覆盖三种场景：微信在前台的全屏来电、微信在后台的顶部横幅、锁屏来电。
- 每 5 分钟检查一次前台 App：**前台是日历/微信/FaceTime 时不操作，三者都不是时才打开日历**（不会打断你手动使用微信或 FaceTime）。
- 微信通话挂断后**不立即切回日历，1 小时后再切回**（期间不做任何拉回操作，你可以自由使用设备）。
- **远程自动更新**：每天 0 点（本地时间）+ 启动时各检查一次更新源，发现新版自动下载、覆盖、重启生效，全程无人值守。
- **失败自动回退**：更新后的新版本若未能正常运行（连续 2 次未通过健康检测，或主循环抛异常），自动恢复 `.bak` 备份的上一版本，并跳过该坏版本号，避免反复更新到同一个坏版本。
- 可选：开机自动启动脚本、屏幕防休眠（`keepAutoTouchAwake`）。

## 原理

脚本是一个常驻循环（需以 Daemon 方式运行）：

1. 每 10 秒截图识别一次，找微信的绿色“接听”按钮（全屏版 + 横幅版两张模板图）。
2. 找到后点击接听，然后轮询红色“挂断”按钮判断通话是否还在进行。
3. 视频通话时控制条会自动隐藏，脚本会轻点屏幕中央把它唤出来再检测，避免误判“通话已结束”。
4. 检测到通话挂断后，记下一个“1 小时后切回日历”的延迟任务；平时每 5 分钟检查一次前台 App，前台为日历/微信/FaceTime 时不动，其他情况才把日历拉回前台。延迟任务到期时，除非前台已是日历或正在 FaceTime，否则切回日历（延迟期间不做任何拉回，完全交给你使用）。

## 需要准备的 3 张素材图（关键步骤）

脚本靠图像识别工作，**接听/挂断按钮图必须在你自己的设备上截图裁剪**，微信不同版本按钮样式不同，别人的图不一定能匹配。

| 文件名 | 内容 | 适用场景 |
|---|---|---|
| `answer_full.png` | 全屏来电界面中的**绿色圆形接听按钮**（连图标一起裁，多带一小圈背景） | 微信在前台时来电、锁屏来电 |
| `answer_banner.png` | 屏幕顶部横幅通知里的**绿色接听按钮** | 微信在后台时来电 |
| `hangup.png` | 通话界面底部的**红色圆形挂断按钮** | 通话进行中/通话结束检测 |

截图裁剪方法（任选其一）：

- 方法 A：让微信来电出现，长按音量减键呼出 AutoTouch 面板 → 点 **Snap** 截图（自动存到相册“AutoTouch”相册）→ 在 AutoTouch 脚本列表点 **+** → **Copy Image Here** 把裁剪好的按钮图拷进脚本目录。裁剪可以用系统相册编辑或任意图片工具。
- 方法 B：打开 AutoTouch 设置里的 **Web Server**，电脑浏览器访问提示的地址，直接把图片上传到脚本目录。

注意：

- **iPhone 和 iPad 屏幕分辨率不同，两台设备要分别在各自设备上截图**；脚本本身通用，拷同一份即可。
- 裁剪范围不要太大（按钮本身 + 一圈背景即可），太大容易匹配失败。

## 安装与运行

1. 把 `wechat_auto_answer.lua` 和三张 PNG 放到 AutoTouch 的 Scripts 目录（`/var/mobile/Library/AutoTouch/Scripts/`）。
2. 打开 AutoTouch → 长按音量减键呼出控制面板 → 选择脚本 → **播放设置(Play Settings)里打开 "Run as Daemon"**（这是后台运行的关键，不打开则切到别的 App 时脚本会停）。
3. 运行脚本。首次运行会自动注册开机自启（`setAutoLaunch`），并把日历 App 拉到前台。
4. 手机设置：**设置 → 显示与亮度 → 自动锁定 → 永不**；保持设备解锁、长期插电（脚本 24 小时轮询，耗电）。
5. 微信侧：确认微信通知权限开着（语音/视频通话提醒开启），不要用“清后台”把微信划掉。

## 如何换日历/时钟 App

脚本顶部配置区改 `CALENDAR_APP_ID` 即可：

1. 把脚本顶部 `IDENTIFY_APP_MODE` 改成 `true`，保存并运行。
2. 手动打开你想用的日历/时钟 App，屏幕上会 toast 显示它的 Bundle ID（同时写入 AutoTouch 日志）。
3. 记下这个 ID，填回 `CALENDAR_APP_ID`，再把 `IDENTIFY_APP_MODE` 改回 `false`。

系统日历的 Bundle ID 是 `com.apple.mobilecal`，微信是 `com.tencent.xin`，FaceTime 是 `com.apple.facetime`。

## 更新功能（远程自动更新）

脚本支持全自动更新：**每天 0 点（设备本地时间）检查一次更新源，启动时也会检查一次**。发现新版本后自动执行：下载 → 语法预检 → 备份旧版 → 覆盖 → 重启 SpringBoard（respring）→ 开机自启自动拉起新版，全程不需要你操作。你唯一的感知是屏幕闪一下、转几秒圈，然后回到日历界面。

### 服务器端准备

在你自己的服务器（建议 HTTPS）建一个静态目录，放两个文件：

```
/autotouch/
├── version.txt          # 内容就是版本号整数，例如：2
└── wechat_auto_answer.lua   # 新版本脚本
```

发布新版流程：修改脚本里的 `VERSION`（+1）→ 把新脚本上传覆盖 `wechat_auto_answer.lua` → 同步更新 `version.txt` 为同一个数字。设备会在下一次检查时自动更新。

### 脚本端配置（顶部配置区）

| 配置项 | 说明 |
|---|---|
| `VERSION` | 当前版本号（整数），发新版时 +1 |
| `UPDATE_BASE_URL` | 更新源目录地址，末尾带 `/`，例如 `https://你的域名/autotouch/`；**留空 = 关闭更新功能** |
| `CHECK_ON_STARTUP` | `true` = 启动时也检查一次（方便验证新版）；`false` = 只在每天 0 点检查 |

### 安全机制（内置）

- 下载文件先写入临时文件，用 Lua `loadfile` 做**语法预检**，语法不过就放弃更新、旧版继续跑；
- 覆盖前自动把旧版备份为 `wechat_auto_answer.lua.bak`，新版出问题可拷回恢复；
- 覆盖前会再次确认开机自启（`setAutoLaunch`）已注册，避免 respring 后新版不自动运行；
- 更新源必须是**你自己可控**的地址，建议 HTTPS。

### 失败自动回退（内置）

更新不是一次性的赌注：如果新版本有 bug 跑不起来，脚本会自动退回上一版本。

**判定规则**
- 每次更新后，新版本处于"待证明"状态，必须**连续正常运行满 60 秒**（`HEALTH_GRACE_S`）才会被标记为健康；
- 新版本**连续 2 次**启动都没能通过健康检测（崩溃、启动即失败，或在 60 秒内被手动停止后再次启动）→ 判定失败；
- 主循环抛出运行时异常且本版本尚未健康 → 立即判定失败。

**回退动作（全自动）**
1. 用 `loadfile` 先检查 `.bak` 备份的语法，没问题才恢复；
2. 把 `.bak` 覆盖回主脚本，记录被跳过的版本号，然后 `respring()` 重启生效；
3. 回退后的旧版本会**跳过该坏版本号**，不会反复更新回同一个坏版本——你要发修复版时，把版本号继续往上加（如坏的是 2，修复版发 3）即可；
4. 如果 `respring` 失败，脚本会直接停止，你手动重新运行一次就会跑回退后的旧版。

**配套文件**：脚本目录下会多一个 `wechat_auto_answer.state`（运行状态文件），记录版本号、健康标记、待跳过版本。手动删除它 = 重置回退记录（不删备份）。

**已知边界**：若新版在启动的最初几毫秒内崩溃（还没写状态文件），可能无法自动识别为"更新失败"，此时需手动重跑一次触发回退；普通运行中的偶发异常会先自动重试一次，重试仍失败且本版本未健康时才回退。

### 注意事项

- respring 会让设备闪屏几秒、所有 App 被清到后台——对本场景无影响，脚本重启后会自动把日历拉回前台；
- 更新检查只在主循环空闲时进行，通话进行中不会打断；
- 如果 respring 失败（日志里会有提示），手动停止再运行一次脚本即可。

## 测试步骤

1. 先确认日历 App 被自动拉到前台。
2. 用另一台设备（或微信小号）拨打视频/语音 → 观察是否自动接听（最长等 10 秒左右）。
3. 挂断后确认**不会**马上回到日历（1 小时内不动），1 小时后自动切回日历。
4. 打开微信用一会儿，确认脚本不会把你强行拉回日历（5 分钟内前台是微信时不动）。
5. 打开 FaceTime 用一会儿，确认同样不会被拉回。
6. 看 AutoTouch 的 Log 面板，应有 `[auto-answer]` 和 `[update]` 开头的日志。
7. 测试更新功能：把服务器 `version.txt` 改成比脚本 `VERSION` 大的数字（如脚本是 1，服务器写 2），重新运行脚本（`CHECK_ON_STARTUP` 为 true 时会立即检查）→ 观察设备自动闪屏重启 → 重启后在 Log 里确认新版本号生效。
8. 测试回退功能：在服务器放一个**故意写错语法**的新版（如 `version.txt` 写 3，脚本里缺个 `end`）→ 脚本自动更新后会因语法预检失败而放弃（这是第一道防线）；若想测真实回退，可放一个能启动但启动后立刻崩溃的版本，观察脚本自动恢复到上一版本并在 Log 出现 `[rollback]` 记录。

## 调参（都在脚本顶部配置区）

| 问题 | 调整 |
|---|---|
| 来电报铃了但没自动接听 | 把 `MATCH_THRESHOLD` 从 `0.90` 调到 `0.85`；或重新裁剪按钮图（多带一点背景、确保清晰） |
| 希望接听更快/更省电 | 把 `POLL_MS` 调小（更快，更耗电）或调大（更省电，响应更慢） |
| 没来电却误点了（如聊天页绿色按钮被当成接听） | 把 `MATCH_THRESHOLD` 调到 `0.95`~`0.98`；确认 `answer_full.png` 是来电界面的大圆按钮而不是小按钮 |
| 通话结束了迟迟不回到日历 | `HANGUP_MISS_LIMIT` 太小可调大；或把 `CALL_POLL_MS` 调小 |
| 屏幕还是会熄 | 确认已关自动锁定；脚本已调用 `keepAutoTouchAwake(true)`，Daemon 模式下生效 |
| 通话挂断后想更快/更晚切回日历 | 改 `POST_CALL_DELAY_S`（默认 3600 = 1 小时；1800 = 半小时） |
| 想让日历被拉回前台更频繁/更少 | 改 `RELAUNCH_S`（默认 300 = 5 分钟；60 = 1 分钟） |
| 想让它只在启动/通话后打开日历，不强拉 | `FORCE_FOREGROUND` 改成 `false` |
| 更新源地址 / 版本号 / 启动检查 | 改 `UPDATE_BASE_URL` / `VERSION` / `CHECK_ON_STARTUP`（详见"更新功能"一节） |
| 失败回退的"健康运行"时长 | 改 `HEALTH_GRACE_S`（默认 60 秒；想更早判定成功就调小） |
| 不想要开机自启 | `AUTO_LAUNCH_ON_BOOT` 改成 `false`（已注册的话可到 AutoTouch 设置里关闭 Auto Launch） |

## 停止脚本

长按音量减键呼出 AutoTouch 控制面板，再长按即可强制停止。

## 风险提示

- **自动接听会直接打开摄像头和麦克风**。请只在你自己可控、且愿意被接听的场景使用；不要放在他人可操作或隐私敏感的环境。
- 脚本基于图像识别，微信改版导致按钮样式变化时需要重新截图。
- 仅用于你本人设备的正常自动化，请勿用于干扰他人或任何违规场景。
